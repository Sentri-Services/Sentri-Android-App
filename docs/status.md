## 巡检离线打卡的后台联网调度（2026-10-22）

API 36 模拟器实测：断网时用已登录的 dev 会话保存一条新巡检打卡，SQLite 状态为 `QUEUED`；测试进程退出后 App 包无进程。仅恢复蜂窝网络、不打开 App，原 WorkManager `NetworkType.CONNECTED` 任务仍未启动。`dumpsys jobscheduler` 显示该任务要求 `VALIDATED`，但模拟器可访问 dev API 的网络只有 `INTERNET`／`PARTIAL_CONNECTIVITY`，因此联网约束不满足。

Android 9 及以上改用只要求 `NET_CAPABILITY_INTERNET` 的 NetworkRequest 约束，旧系统保留 `CONNECTED` 回退；新调度名加版本以重新安排升级前被旧约束卡住的命令，完成后及下次启动时清理旧名任务。同一条排队打卡在离线时重排新后台任务后，App 仍无进程；恢复蜂窝网络 8 秒后直接查询 SQLite，状态变为 `SYNCED`，发送尝试为 1，且有服务端读回回执。该过程没有启动 App 界面或前台同步。最终包覆盖安装并启动后，升级前遗留的旧任务从排队转为取消。

继续测试设备重启时发现：WorkManager 数据库还保留 `ENQUEUED`，但系统作业已消失，内置 `RescheduleReceiver` 在本机处于禁用状态。Android 增加仅负责重排巡检打卡的开机／包更新接收器：从当前登录会话的厂区隔离缓存取账号，只重新安排队列作业；真正发送仍由 Worker 在线核对账号、厂区与用户。API 36 模拟器再次断网保存并重启，开机接收器重建了作业；打卡仍为 `QUEUED|0`。结束接收器进程后只恢复蜂窝网络，8 秒后队列变为 `SYNCED`，尝试次数 1 且有读回回执，WorkSpec 为成功。未打开 App 界面。`scripts/verify.sh` 第一次运行被既有 `HomeTransferDetailRemoteTest` 的 Main dispatcher 跨测试残留异常打断，完整重跑通过；新增的语言作用域缓存断言在 API 36 模拟器单项通过。真机、较旧 Android 版本及不同系统的重启调度尚未验收。
