# 设备报障：本机草稿

2026-10-26。设计基线：Sentri-UI `main@f66affd` 的 Inspection、`inspection.fault-report` 和 `inspection.fault-report-other`；这些页面仍为 `in-design`。用户已确认先做照片前端逻辑，后端支持后再接入。

## 本次调整

原实现只在当前单元的内存中保留表单，照片为临时选择器 URI。重启后无法继续填写，也不能证明照片已保存在本机。

Android 增加“保存本机草稿”：

- 设备类型、其他设备名称、描述和最多 12 张照片可以一起保存，不要求先填完必填字段。
- 照片复制到应用私有文件；所有照片复制成功后再原子替换草稿。发布前失败时保留上一份保存结果，本次新增的临时副本会清理。保存还需同步文件并读回核对；若发布结果无法确认，不提前删除任一版本的照片，提示重试。重新读取时才按有效草稿清理无引用副本。
- 页面区分未保存、保存中、已保存在本机、保存失败。只有收到本机保存结果才显示已保存。
- 保存后重启、离开单元再回来可恢复。未保存的修改仍只在本单元会话内保留，不自动覆盖已保存版本。
- 清空草稿同时清除其保存内容和照片；失败时提示重试。移除照片后再次保存，才删除已保存副本，避免破坏上一份草稿。
- 按环境、登录身份、业务用户、厂区、单元、栏位隔离；身份或单元改变时清除页面状态，重新读取对应草稿。异步结果不能回填到另一次页面会话。
- 草稿文件损坏时先提示重试，不用空表单覆盖；个别照片缺失时保留表单和附件位置，提示移除后重新添加，不显示完整保存成功。

本机暂按每张 20 MiB 控制文件复制，防止无界占用存储；页面以 20 MB 提示。这是客户端存储限制，不代表未来服务端附件能力已确定。最终数量、类型和大小仍需后端能力接口明确。

## 边界

这是一份未提交的表单草稿，不是待同步报障，不进入上传队列，联网不会自动上传，也不生成故障记录、打卡或其他业务写入。“报告故障”保持禁用。报障正式保存、附件上传及回执仍见 [后端契约清单](backend-adjustments.md#backend-contract-proposal)。

页面使用现有 Sheet、Row、Button；没有改共享组件。此为 Android 局部补充，尚未回写 Sentri-UI，也未改变 feature 成熟度。

## 验证

API 36 三项定向设备用例通过：

- 原图删除后的私有副本读取、重新建立存储对象后的恢复、四项账号／厂区维度及单元／栏位隔离、复制中途失败保留旧版本、清空照片清理、缺图保留与提示。
- 新巡检 ViewModel 恢复草稿、未保存修改不覆盖旧版本、错误 lease 拒绝保存、清空持久化。
- 栏位报障表单 → 填写 → 保存本机草稿 → 仍不可报告 → 返回再进入 → 清空；UI 的保存回执使用 fixture。

这些不等同于真实设备相册或系统杀进程验证。真实相册临时授权、保存时进程被杀／断电、磁盘不足、20 MiB 边界、旧系统与真机、大量照片性能仍未验证，见 [统一待测清单](home-inspection-health-delivery.md)。没有进行真实后端报障或清空登录。最后仅补图片加载占位复位，未重跑设备用例；该增量后的 `verify.sh` 通过：275 JVM、Lint 无错误（有警告）、双语和 GraphQL 契约。


2026-10-26 补充：发现 `AtomicFile.finishWrite` 的同步／重命名失败可能仅记日志，不应仅凭正常返回发“已保存”回执。依据 [AOSP AtomicFile 源码](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/core/java/android/util/AtomicFile.java)，Android 增加显式文件同步、提交后原样读回，以及发布结果未确认时延迟清理照片；首次保存中断而没有有效表单时也清理孤立副本。API 36 定向用例已覆盖已有草稿旁的未完成替换、首次未完成保存的遗留文件恢复；这不等于真实断电或磁盘耗尽测试。
