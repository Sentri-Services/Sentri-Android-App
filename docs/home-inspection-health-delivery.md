## 每条写入的验收门槛

填写、原子本机保存、重启恢复、恢复网络后发送、严格回执、刷新读取确认分别留下证据。本机保存只显示待同步；结果不明确时先核对服务器原结果，不能自动重发。没有可靠的服务端确认手段时，把该写操作放入[后端调整清单](backend-adjustments.md)，继续做独立读路径。

## Android 局部反馈：栏位备注草稿

设计基线为 Sentri-UI `main@f66affd` 的 `inspection.pen-note`（仍为 `in-design`）。设计要求一栏一条当前备注，编辑与关闭保留历史；旧后端只有单元备注，无法准确替换或关闭本栏备注。

Android 在栏位详情提供“栏位备注”入口，使用现有 Sheet／Row／Button。当前只编辑本机草稿，空白不能保存；返回保留当前单元的未保存内容，显式保存后重新进入可恢复，清空只作用于这份本机草稿。读取失败先重试，也可明确清空坏草稿后重填，不自动拿空表单覆盖。无服务端作者、时间或“已归档到日志”的假状态，正式保存备注保持禁用。

草稿使用独立存储种类和单元＋栏位键，账号、厂区等由已有 SQLite 作用域隔离；它不是只读接口快照，不进入只读页淘汰名单，也不是上传命令。保存时间仅是本机草稿时间。切换作用域后清除页面状态，迟到结果不回填新页面；未保存修改不覆盖已保存版本。

API 36 三项定向用例通过：SQLite 关闭重开／范围隔离／空白拒绝／坏草稿主动清空恢复；巡检 ViewModel 重建、错误 lease 拒绝、保存版本恢复和清空；页面入口→填写→返回再开→保存本机草稿→正式保存仍禁用→清空。后两项使用 fake 会话／页面 fixture，不等同于真实 dev 或真机。最新增量仅做语言、APK／测试包与以上设备验证，完整脚本留下一版本检查点。没有回写 Sentri-UI 或改共享组件。
